OAS-контракт для REST API
Цель бизнеса: Обеспечить клиентские приложения (веб, мобильные) быстрым и удобным доступом к структурированному каталогу товаров: корневые категории (Электроника, Одежда, Обувь и т.д.) с вложенными подгруппами для навигации и фильтрации.

Контекст: Маркетплейс расширяет ассортимент до 50+ категорий и 500+ подкатегорий. Каталог часто меняется (администраторы добавляют/редактируют группы). API должно работать с высокой нагрузкой и поддерживать кэширование на стороне клиента. 

Бизнес-требование
Сервис каталога групп должен предоставлять REST API для:

Получения всех корневых категорий первого уровня;
Получения подкатегорий определённой группы – дочерние элементы по ID категории первого уровня;
Получения полного дерева каталога (все категории и подкатегории в виде вложенной структуры).
Административный функционал (для контент-менеджеров):
Создание новой категории/подкатегории с parent_id;
Редактирование категории;
Удаление категории.

Атрибуты сущности «Категория» (группа товаров):
Атрибут	Тип	Обязательность	Описание
id	string (UUID)	да	Уникальный идентификатор
name	string	да	Название (например, «Смартфоны», «Кроссовки»)
slug	string	да	URL-дружественный идентификатор (уникальный)
description	string	нет	Краткое описание
parent_id	string (UUID)	нет	ID родительской категории (null для корневых)
level	integer	нет	Уровень вложенности (0 – корневая) – вычисляемое поле
image_url	string	нет	Ссылка на иконку/картинку категории
is_active	boolean	да	Активна ли категория (отображать в каталоге)
display_order	integer	да	Порядок сортировки при выводе
created_at	string (date-time)	да	ISO 8601
updated_at	string (date-time)	да	ISO 8601

Нефункциональные требования
Протокол: HTTPS;
Формат обмена: JSON;
Пагинация для списков подкатегорий: параметры limit (max 100) и offset (или page). По умолчанию limit = 50;
Сортировка: по display_order (по возрастанию), затем по name;
Фильтрация для подгатегорий по is_active (только активные);
Поиск по name (частичное совпадение, регистронезависимое) – через параметры запроса search;
Кэширование: для метода получения дерева категорий через заголовки Cache-Control: max-age=3600 (1 час), так как дерево меняется редко;
Ошибки: стандартные HTTP коды – 400 , 401, 404 , 409 (конфликт при создании дубликата имени), 500;
Дедупликация при создании категории через использование ключа идемпотентности;
Группировка методов: необхдимо предусмотреть разделение методов на публичные и админские методы;
Аутентификация: для методов контент-менеджера(администратора) требуется авторизация через bearerAuth. Для публичных – не требуется;
Версионирование: через URI (/api/v1/...).
